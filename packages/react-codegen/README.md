# foldkit-react-codegen

Compile Foldkit view functions to React TSX source. It works on the TypeScript
syntax tree, so the output keeps your variable names, control flow, helpers,
and imports. When a construct has no faithful React translation, it refuses
with a located diagnostic instead of guessing.

```text
view(model, h: HtmlBuilder<Message>): Html
        │  foldkit-react-codegen
        ▼
view(model, dispatch: (message: Message) => void): ReactNode
```

## When to use it

- **Use it** to get portable React rendering code for views that are plain
  markup, attributes, and events: a design-system handoff, a React port, or
  sharing presentational views with a React app.
- **Do not use it** to run a Foldkit application inside React. The output is
  only the view: no Model, `update`, Commands, Subscriptions, or Mounts. To
  embed a whole program, or to use a React component from a Foldkit view, use
  [`foldkit-react`](../react/README.md), which keeps every Foldkit semantic.

The compiled view owns nothing. Whatever calls it supplies `model` and
`dispatch`, typically a React component holding the state, or a Foldkit program
through `foldkit-react`.

## Install

```sh
pnpm add -D foldkit-react-codegen typescript
```

## Sixty seconds

```ts
// src/SaveButton.ts
import type { Html, HtmlBuilder } from 'foldkit/html'
import { Message, type Model } from './message'

export const view = (model: Model, h: HtmlBuilder<Message>): Html =>
  h.button([h.Class('save'), h.Disabled(model.saving), h.OnClick(Message.Saved())], ['Save'])
```

```sh
pnpm foldkit-react-codegen src --out-dir generated
```

```tsx
// generated/src/SaveButton.tsx
// @generated by foldkit-react-codegen from src/SaveButton.ts. Do not edit.
import type { ReactNode } from "react";
import { Message, type Model } from './message';
export const view = (model: Model, dispatch: (message: Message) => void): ReactNode => (<button className={'save'} disabled={model.saving} onClick={() => dispatch(Message.Saved())}>Save</button>);
```

Use it from React:

```tsx
const [model, setModel] = useState(initialModel)
// `next` is your transition: (model, message) => model
return view(model, message => setModel(current => next(current, message)))
```

What the compiler did:

- Every function with an `HtmlBuilder` parameter is a view. Its builder
  parameter became `dispatch`, and its `Html` types became `ReactNode`. A helper
  view called as `row(item, h)` becomes `row(item, dispatch)`, so views still
  compose.
- `h.<tag>(attributes, children)` became a JSX element, and each attribute
  became a prop using the table below.
- Everything else, such as the ternaries, `map` calls, local helpers, and
  imports, is copied through unchanged.

The output is not formatted. Run your formatter over the out dir if you commit
it.

## What compiles

| Foldkit | React |
| --- | --- |
| `h.div(attributes, children)`, any HTML/SVG/MathML tag | `<div …>…</div>` |
| `h.keyed('li')(key, attributes, children)` | `<li key={key} …>` |
| `h.empty` | `null` |
| `Class`, `Id`, `Key`, `For`, `Tabindex`, `Readonly`, … | `className`, `id`, `key`, `htmlFor`, `tabIndex`, `readOnly`, … |
| `AriaLabelledBy(x)` and every `Aria*` | `aria-labelledby={x}` |
| `Attribute('k', v)`, `DataAttribute('k', v)` | `k={v}`, `data-k={v}` |
| `Style({ 'background-color': c })` | `style={{ backgroundColor: c }}` |
| `OnClick(message)`, `OnFocus`, `OnBlur`, mouse enter/leave/over/out/down/up/move, `OnDoubleClick` | `onClick={() => dispatch(message)}` |
| `OnInput(f)` | `onChange={event => dispatch(f(event.currentTarget.value))}` |
| `OnKeyDown(f)`, `OnKeyUp(f)` | `onKeyDown={event => dispatch(f(event.key, { shiftKey, ctrlKey, altKey, metaKey }))}` |
| `OnSubmit(message)` | `onSubmit={event => { event.preventDefault(); dispatch(message) }}` |

`OnInput` becomes React's `onChange` on purpose. On a text control, React's
`onChange` fires on every native `input` event, and pairing it with `value`
keeps the input controlled without a warning.

## What it refuses

Each refusal prints `file:line:column - error CODE: message`. If any file has a
diagnostic, the CLI writes nothing and exits with status 1.

| Code | Cause |
| --- | --- |
| `FKREACT0001` | A builder with no standalone JSX form: `h.submodel`, or `h.keyed` with a computed tag |
| `FKREACT0002` | An attribute without a faithful React equivalent: `OnMount`, `OnUnmount`, `OnChange` (the native `change` event, which React's `onChange` is not), `InnerHTML`, and anything not in the table |
| `FKREACT0003` | Attributes the compiler cannot see: a non-literal attribute array, a spread, or an attribute built outside an element |
| `FKREACT0004` | The builder stored or used other than calling it or passing it to a helper view |
| `FKREACT0005` | An argument it cannot lower: click options, `Style` without an object literal, `Attribute` with a computed name |

For any of these, keep that part in Foldkit and use `foldkit-react`, or write
it in React.

## Semantic differences to know

- **Messages are built when the event fires.** Foldkit builds the Message when
  the view renders; the compiled handler builds it on click. The two are the
  same when Message constructors are pure, which Foldkit views assume.
- **Keys are React's.** Foldkit's keyed lists do not need keys. React warns
  about unkeyed lists, so use `h.keyed` or `h.Key` in lists you compile.
- **Only the listed attributes are checked against Foldkit's behavior.** An
  attribute missing from the table is refused rather than guessed.

## CLI

```text
foldkit-react-codegen <file-or-directory>... --out-dir <directory> [--root-dir <directory>]
```

- Directories are searched for `.ts` files, skipping `.d.ts` and `.test.ts`.
- Each output lands at `<out-dir>/<path relative to root-dir>.tsx`. The root
  dir defaults to the working directory.
- A file whose output bytes are unchanged is not rewritten, so watchers and git
  see no churn.
- Files without views are copied with a header, so relative imports between
  compiled files resolve inside the out dir. Imports of files you did not
  compile will not resolve from there.

## Library API

```ts
import { formatDiagnostic, generate, transformSourceFile } from 'foldkit-react-codegen'

const result = transformSourceFile('src/SaveButton.ts', sourceText)
if (result.ok) {
  console.log(result.code)
} else {
  result.diagnostics.map(formatDiagnostic).forEach(line => console.error(line))
}

await generate({ inputs: ['src'], outDir: 'generated' })
```

`transformSourceFile` is pure: text in, text or diagnostics out.

## Not yet

Source maps, watch mode, Submodels, `OnMount`, and custom elements are not
supported yet.
