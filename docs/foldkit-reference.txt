## Foldkit API Quick Reference

Foldkit is an Effect-native Elm-style frontend framework. Prefer these primitives over inventing React-style state/lifecycle patterns.

### Core modules

- **`AsyncData`** — async/loading state.
  - `Idle`, `Loading`, `Refreshing`, `Success`, `Failure`, `Stale`
  - `succeed`, `fail`
  - `match`, `matchData`, `matchDataSplitEmpty`
  - `map`, `mapError`, `mapBoth`, `flatMap`
  - `getData`, `getError`, `getOrElse`
  - `revalidate`, `revalidateOrLoad`, `loadIfMissing`
  - `zipWith`, `all`, `settle`

- **`Command`** — one-shot side effects.
  - `define` — define a named Effect-backed Command.
  - `mapMessage`, `mapMessages` — map result Messages.
  - `mapEffect` — transform underlying Effect.
  - `Interruptible` — cancellable/restartable Commands.
  - Types: `Command`, `CommandDefinition`.

- **`Update`** — compose update results and child state machines.
  - `Return` — standard `{ model, commands? }` update result.
  - `ReturnWithOutMessage`
  - `Step`, `StepWithOutMessage`
  - `combine` — combine update results.
  - `foldChild` — run a child update inside a parent update.
  - `foldChildStep`
  - `foldChildInit`, `foldChildInits`
  - `withOutMessage`
  - `refresh`

- **`Message`** — define typed Message unions.
  - `defineMessageUnion`
  - `MessageUnion`

- **`Schema`** — Foldkit helpers around Effect Schema.
  - `defineTaggedUnion`
  - `taggedStruct`

- **`Struct`** — immutable Model updates.
  - `modifyFields`
  - `makeModifyFieldsFor`

- **`Submodel`** — nested Model/Message/update state machines.
  - `defineView`
  - `Config`
  - `View`
  - `Reflect`, `Reflect2`

### Runtime / application

- **`Runtime`** — create and execute Foldkit applications.
  - `makeApplication`

  - `run`
  - `embed`
  - `hydrate`
  - `ApplicationInit`, `ElementInit`
  - routing configuration

  - view transitions

- **`Port`** — typed host ↔ Foldkit communication.
  - `inbound`
  - `outbound`
  - `emit`
  - `stream`
  - `subscription`
  - `Ports`

- **`Render`** — post-render lifecycle.
  - `afterCommit`
  - `afterPaint`

- **`brand`** — internal/result branding helper.
  - `brandViewResult`

### Effects / lifecycles

- **`Subscription`** — ongoing external streams driven by Model state.

  - `animationFrame`

### Testing

- **`Story`** — test pure update/state-machine behavior.
  - `story`
  - `given`
  - `message`
  - `model`
  - `steps`
  - `expectOutMessage`
  - `expectNoOutMessage`
  - `Story.Command.resolve`
  - `Story.Command.resolveAll`
  - `Story.Command.resolveAllExact`
  - `Story.Command.expectHas`
  - `Story.Command.expectExact`
  - `Story.Command.expectNone`

- **`Scene`** — test rendered behavior/accessibility.
  - queries: `getByRole`, `getByText`, `getByLabel`, `getByTestId`, etc.
  - `find`, `findAll`
  - `role`, `text`, `label`, `selector`, `within`
  - `first`, `last`, `nth`, `filter`
  - interaction helpers for click/input/change/keyboard/files/etc.
  - Command and Mount resolution helpers
  - prefer Scene for user-visible behavior; Story for Model assertions.

- **`foldkit/test`** — exports `Story` and `Scene`.
- **`foldkit/test/vitest`** — Vitest integration/matchers.

- **`Anchor`** — positioning/portal runtime for custom floating UI.

Stateless UI modules generally expose `view`. Stateful UI modules expose a Foldkit-style `Model`, `Message`, `init`, `update`, `view`, and often `OutMessage`.

### Selection rules

- async request state → `AsyncData`
- one-shot effect → `Command`
- update composition → `Update`
- immutable Model edit → `Struct`
- nested state machine → `Submodel`
- ongoing stream → `Subscription`
- long-lived stateful handle → `ManagedResource`
- imperative DOM/library → `Mount`
- host ↔ Foldkit boundary → `Port`
- URL parsing/building → `Route`
- navigation effect → `Navigation`
- validation → `FieldValidation`
- update tests → `Story`
- UI behavior tests → `Scene`
- browser rendering → `Html`
- application execution → `Runtime`

Foldkit is pre-1.0. Verify exact signatures against the installed Foldkit version/source before inventing APIs.
