Checked against metakit 0.1.0, effect 4.1.4.

# `metakit`

Use `metakit` when you want one inspectable Effect `Schema` + `Transition` declaration to drive runtime validation, partial evaluation (disabled buttons / agent affordances), SQL or Drizzle `CHECK`/`WHERE`/`UPDATE`, static dependency & SSR pruning, and Zone/Z3 proofs—without pulling in Foldkit.

Use `foldkit-entity` + `foldkit-guard` instead when you want Foldkit's entity relations, Remote/Sync wiring, and CRUD/CMS adapters.

## Normal path

```ts
import { Effect, Result, Schema } from 'effect'
import { Eq, Expr, Num, Path, Transition } from 'metakit'
import { Money } from 'metakit/domain'
import * as Graph from 'metakit/graph'
import * as Machine from 'metakit/machine'
import * as Prove from 'metakit/prove'
import * as Sql from 'metakit/sql'

const Usd = Money.make('USD')

const Account = Schema.Struct({
  id: Schema.String,
  balance: Usd,
  reserved: Usd,
  status: Schema.Literals(['open', 'frozen']),
}).pipe(
  Expr.refine($ =>
    Expr.all(Num.gte($.balance, 0), Num.gte($.reserved, 0), Num.lte($.reserved, $.balance)),
  ),
)

const Withdraw = Transition.make({
  state: Account,
  input: Schema.Struct({ amount: Usd }),
  when: ({ state, input }) =>
    Expr.all(
      Eq.is(state.status, 'open'),
      Num.gt(input.amount, 0),
      Num.lte(input.amount, Num.sub(state.balance, state.reserved)),
    ),
  apply: ({ state, input }) => [
    Transition.set(state.balance, Money.sub(state.balance, input.amount)),
  ],
})

const AccountMachine = Machine.make({
  state: Account,
  transitions: { Withdraw },
})

const check = Result.getOrThrow(Sql.toCheck(Account, { dialect: 'postgres' }))
const $ = Path.from(Account)
const analysis = Graph.analyze(AccountMachine, {
  available: Num.sub($.balance, $.reserved),
  accountId: $.id,
})
const proof = await Effect.runPromise(Prove.machine(AccountMachine, { pin: ['Withdraw'] }))
void check
void analysis
void proof
```

## Mistakes to avoid

- **Wrapping `Money.make('USD')` with `.schema`.** `Money.make('USD')` is already a `Schema.Codec<MoneyValue<'USD', 2>, number>`. Only `CalendarDay.schema`, `Text.schema` and `OrderedEnum.make(...).schema` expose `.schema`.
- **Using `Num.sub` to assign back to a `Money` field.** `Num.sub` returns `Expr<Env, number>`, which drops the currency brand. Use `Money.add` / `Money.sub` so `Transition.set(state.balance, ...)` keeps currency and scale safety.
- **Passing 3 positional args to `Expr.when` or a bare string to `Expr.opaque`.** Use `Expr.when(cond, { then, else })` and `Expr.opaque({ name: '...', reads: [...] }, fn)`.
- **Conflating `null` with missing (`Unknown`) in partial evaluation.** `{ discount: null }` is a known `null` (folds to a literal in `Expr.residualize` and `Graph.pruneStatic`); omit the key to leave it `Unknown`.
- **Expecting a proof over plain `Schema.Number`.** Evaluation refuses to order `NaN`, so a rule that compares one does not hold, and no check proves anything that reads a number that may be `NaN`: `Abstract.*`, `Prove.*` and the `metakit/policy` checks answer `Unknown` and name the path. Declare a compared number `Schema.Finite` or `Schema.Int`.
- **Expecting a comparison of a null to hold.** A value that may be null (`Schema.NullOr`, `Schema.optionalKey`, a field under a nullable parent) makes every operator over it null, and a rule holds only where it is true. `Prove.*` reads it so: `Ord.gte(row.left, 0)` over a nullable `left` is refuted by the null, and `Expr.any(Null.isNull(row.left), Ord.gte(row.left, 0))` is proved. The synchronous `Abstract.*` checks leave such a goal `Unknown`.
- **Expecting a rule over a `Schema.String` field to be proved.** Every text and equality operation (`Eq.is`, `Eq.equals`, `Eq.oneOf`, `Str.*`) refuses text holding a NUL character, which Postgres cannot store, and a `Schema.String` admits one. The checkers answer `Unknown` for such a rule unless a rule they assume already took the text without refusing it; a field of `Schema.Literals` holds no NUL. Declare the field `Text.schema` from `metakit/domain`, which refuses a NUL where it is decoded, and the rule can be proved.
- **Expecting `false` to decide an `and` over a refusal.** A refusal decides before null and is not absorbed: `Bool.and(false, x)` and `Bool.or(true, x)` are refused where `x` is, and a strict operator refuses text holding a NUL or NaN beside a null operand. `Expr.residualize` and `Expr.judge` drop the other side only where its Schemas say it cannot be refused (a finite number, a boolean, a literal set, `Text.schema`, or an `Arr.any`/`Arr.every` or exists over a list or related rows whose test reads only those).
- **Comparing an `Option` field with `Option.none()`.** A path to an `Option` field (`Schema.Option`, `Schema.OptionFromNullOr`) reads as its value or null: test it with `Null.isNull(state.editingId)` or `Eq.isNot(state.editingId, null)`, and write `Transition.set(state.editingId, null)` to store `Option.none()`. A write to a field inside an `Option` is refused; write the whole value.
- **Expecting integer arithmetic past 2^53 − 1 to be proved.** Evaluation refuses a result outside the safe range, so `Prove.*` refutes a goal that needs one. Bound the fields.
- **Importing `metakit/sql`, `metakit/drizzle`, `metakit/aggregates/sql` or `metakit/prove` in browser bundles.** Keep browser code on `metakit`, `metakit/domain`, `metakit/aggregates`, `metakit/machine`, and `metakit/inspect`.
- **Building a SQL `UPDATE` from an input that was never checked.** `Sql.toUpdate` and `Drizzle.toUpdate` refuse (`Refused`) an input the transition's input Schema refuses; a fraction beside an integer column, `NaN`, an infinity, and two paths that come to one column name (`a_b` and `a.b`) are `SqlUnsupportedError`.

## Main exports by subpath

- `metakit`: `Path`, `PathAccessor`, `Expression`, `SchemaOf`, `Expr`, `Bool`, `Eq`, `Null`, `Ord`, `Num`, `Time`, `Str`, `Arr`, `Sets`, `Transition`, `Verdict`, `Abstract`, `opProperties`
- `Sets` (`set.union`, `set.intersect`, `set.difference`, `set.subset`, `set.disjoint`, plus derived `symDiff`, `equal`, `superset`, `properSubset`, `overlaps`, `include`, `exclude`, `has`, `count`, `isEmpty`, `nonEmpty`): canonical ascending unique scalar sets with native Z3 `SMTSet` theorem proving (De Morgan, distributivity, absorption, symmetric difference, subset partial order, RBAC invariants) and concrete counterexample witnesses.
- The 33 core operators (the `CoreOpId` union) include SQL's `=` and `in` (`Eq.equals`, `Eq.among`: null for a null value, and `among` null where nothing matches beside a null candidate, false among no candidate whatever the value; both refuse NaN; `Eq.is` and `Eq.oneOf` never give null), `Str.lowerAscii` (A to Z only), `Str.trim` (space, tab, LF, CR), the code-point orders `Str.lt`, `Str.lte`, `Str.gt`, `Str.gte`, and `Null.coalesce(value, fallback)`. Text is compared by character: a lone surrogate reads as U+FFFD.
- `Expr.evalResult(expr, env)` gives the value, null (an operand was null or its key absent), or the `Node.Refusal` of an integer past 2^53 − 1, a non-finite number, an operand of the wrong type, a `Match` value no case names, text holding a NUL (`unportable`), a foreign operation with no implementation (`unsupported`) or one whose implementation threw (`failed`). `Expr.eval` returns the value and throws the refusal. `Expr.holds(rule, env)` is true only where the rule evaluates to true. An operator takes a nullable operand and its result type then includes `null`.
- `Node.foreign({ id, version, returns, nulls })` declares an operation your application implements; build a call of it with `call` from `metakit/build`. Evaluation, `Expr.residualize` and `Expr.judge` take its implementation under its `id@version` (`Node.foreignName(op)`) as `{ foreign: { 'app.double@1': { run } } }`, `Sql.toWhere` and `Drizzle.toWhere` as `foreign: { 'app.double@1': { sql } }`, so two versions of one operation each have theirs; without one, evaluation refuses, `judge` answers `Unknown`, SQL refuses naming `id@version`, and the checkers answer `Unknown`.
- `Transition.make({ state, input, supplied: { now: Schema.Int, id: Schema.String }, apply })` reads values no caller passes and no state holds as `supplied`; `Transition.run(t, state, input, { now, id })` takes them, and a machine's message carries them as `supplied`. `Transition.add(target, amount)` writes the sum. `Transition.opaque({ name, state, input, reads, writes, run })` declares a step written as code by its footprint; it throws where `run` changes a path `writes` does not name.
- `Transition.run`, `Transition.step`, `machine.dispatch` and `machine.update` take `{ foreign }` last (`Transition.step(t, state, input, undefined, { foreign })` where `t` declares no supplied values), so a transition whose writes call a foreign operation runs; without the implementation the step is refused (`Refused`, naming `id@version`). `Transition.run` and `Transition.step` refuse (`Refused`) an input or supplied value its Schema refuses, a guard that is not true, and a written or emitted value that is refused. `Transition.make` throws for two writes where one target is under the other; `Transition.set` takes its type from the target, so a wider value does not compile. `Transition.lift(path, transition)` is refused where the model holds no child at `path`. `Transition.footprint` gives `reads` from `{ state, input, supplied }`, and `stateReads` and `writes` from the state; a `*` segment stands for every element of a list (`todos.*.title`), and `Path.isPrefix` and `Path.meets` match it against any one segment.
- Lists: `Arr.any`, `every`, `count` (with a test), `sum`, `min`, `max`, `find`, `keep` take the list and an arrow over a path for the element (`Arr.any(state.todos, todo => todo.done)`); the arrow runs once while building and its expression is kept as a `Rows` node, the seventh node kind. A test that is null does not pass; over none `any` is false, `every` true, `count` and `sum` 0, `min`, `max` and `find` null; a null list gives null; an integer total past the safe range is refused. Nested list folds are supported (each nesting level binds its element under a distinct slice so cross-list and self-uniqueness rules work in evaluation, `reads`, `residualize`, and `judge`); a body still holds no opaque term. SQL refuses a list in a column by name; the checker knows only its length after a write; the solver answers `unsupported`.
- A write names its way of writing (`write.way._tag`): `set`, `add`, and over a list `append`, `insert` (unless an element has the key, `id` unless `{ key }` says), `remove`, `removeWhere`, `patch(list, key, todo => ({ done: … }))`, `patchWhere`, and `include` and `exclude` over a set held as a sorted list of scalars. A key no element has gives back the state it was given; every element with a duplicate key is changed or removed. A patch names only the element's fields; an `Option` field takes the value or null.
- `emits: env => [Transition.emit(tag, fields, { when })]`: a step returns the records whose condition is true, each `{ _tag, ...fields }` read over the state before the step; the machine's `update` returns `[state, records]`.
- `Transition.commutes(a, b)` over one state: `True` only where no write of one meets a read of the other, and every two writes to one path are a pair `writeProperties` lists, on its condition (two `add`s, a decrement being the `add` of `Num.neg(amount)`, to integers the checker bounds in range, two removals, `include`s, a `patch` and a removal or two `patch`es of fields apart, two `set`s of one literal); otherwise `Unknown` with a `walk` obligation. Never `False`.
- `Interval` (`top`, `bottom`, `between`, `constant`, `contains`, `within`, `meet`, `join`, `add`, `sub`, `neg`, `mul`, `monotone`, `lt`, `lte`, `is`) and `Zone` are the checker's own domains, exported for tools built on it; bounds round outward. `Abstract.abstractOps` has one row per operator, a `TermOp`, a `PredicateOp` or a `ValueOp`.
- `opProperties` holds what each core operator keeps (`identity`, `absorbing`, `idempotent`, `monotone`, `commutative`, `associative` and `invertible` with the `Domain` each holds over, and `reflexive`, `involution`); partial evaluation and the checker's bounds read it, and `checkAllProperties` in `metakit/conformance` checks each entry against the evaluator. `num.add` is associative and invertible over the integers only. `foldProperties` (per fold) and `writeProperties` (which ways commute on one path) sit beside it, checked by `checkAllFoldProperties` and `checkAllWriteProperties`. Its `set` and `add` rows are also exported alone (`setWrites`, `addWrites`), so code that asks only of those two keeps the rest of the table off a page; `foldkit-remote` reads them to decide whether a pending write's answer over a newer server value needs a second read.
- `metakit/relation`: `Relation.define({ name, parent, child, foreignKey, parentKey?, cardinality?, onDelete? })` (or `Relation.make('Line.owner', Line, options?)`) declares single or composite-key relations with `'one' | 'optional' | 'many'` cardinality; `Relation.any`, `every`, `count`, `sum`, `min`, `max`, `reduce` ask a question of them; `Relation.withRows(row, rel, rows, { whole })` attaches related rows in memory. `Sql.toWhere` and `Drizzle.toWhere` lower relations to correlated subqueries, including self-referential tables (aliased automatically) and composite foreign keys. `Prove.*` enforces cardinality and quantifier count axioms in Z3 (`count(rel, p) <= count(rel)`, `cardinality: 'one' => count === 1 && (any <=> every)`).
- `metakit/fn`: `Fn.make(params, body)` and signature-first `Fn.params(params)` build callable, Schema-typed MetaKit functions with fluent `.where(...)`, `.returns(...)`, `.ensures(...)`, `.body(...)`, `fn.precondition(args)`, `fn.run(args)`, and `fn.runChecked(rawArgs)`. Symbolic calls inline ASTs with hygienic `Rows` binder alpha-renaming (zero new `CoreOpId`s, transparent to SQL, partial eval, and Z3). `Prove.fn(fn)` proves Hoare contracts (`where => defined && returns && ensures`) in Z3; `Inspect.fn(fn)` extracts parameter/return specs and JSON Schemas. `Transition.make` also accepts optional `ensures: ({ state, input, supplied, next }) => Expr` for relational postconditions proved by `Prove.transition` / `Prove.machine`.
- `Abstract.checkTransition(stateSchema, transition)` is `True` only where every rule holds after the writes and every written value is one its field's Schema takes (bounds, also inside `NullOr`; being an integer; a literal of the enumeration; not null). `Abstract.checkGoal(stateSchema, transition, { assume, goal })` decides one goal that reads the state before as `state` and after as `next`. `Abstract.checkInvariant` and both answer `True` for "evaluates to true in every admitted environment" and `False` for "evaluates to false in every one".
- `Expr.rulesOf(schema)` lists each `Expr.refine` and Effect numeric bound with the property path it sits on (`at`, `[]` for the schema itself) and its `message` annotation as an `Option`, so a form can show the message beside the field. `Expr.refinementsOf` gives the expressions alone. Checks inside `Schema.optional`, `Schema.optionalKey`, and `Schema.NullOr` are included, guarded with `Null.isNull(at) || rule`; multi-branch non-nullish unions are not read.
- `metakit/domain`: `Money`, `Decimal`, `CalendarDay`, `Id`, `OrderedEnum`, `Ordinal`, `Text`, `Domain`. `Id.make(entity, { prefix?, minLength?, maxLength? })` builds branded, non-empty, NUL-free entity IDs (`Id.value`). `Ordinal` provides base-62 fractional-index ordering keys (`Ordinal.schema`, `initial`, `between`, `after`, `before`, `lt`/`lte`/`gt`/`gte`). `OrderedEnum` exposes `min`, `max`, `rank`, `next`, `prev`, `distance`, and comparison ops. `Text.schema` is `Schema.String` refusing a NUL; the checkers and partial evaluation read a field of it as text no operation refuses. `Decimal.format(value, { scale })` and `Money.format(amount, code, { scale })` take the value's own scale. `Decimal.mul` and `Money.mul` build the core operation `num.mulScaled` (`Num.mulScaled(a, b, { shift })`): exact integer products rounded half-even, refused (not `null`) where the product, an operand or the result leaves ±(2^53 − 1). Evaluation, `Expr.judge`, SQL on SQLite and Postgres (`NULL` where evaluation refuses; a column not known to be an integer is refused by name), the checkers (bounds from the operands' intervals) and Z3 (exact; `Unknown` for non-linear or non-integer operands) read it, and `Rows.sum` takes it as an integer contribution. A `Null.isNull` of a refused product holds in SQL and is refused in memory. `CalendarDay.toIso` and `fromIso` return a `Result` over years 0001 to 9999 (`CalendarDay.earliest` to `CalendarDay.latest`).
- `metakit/aggregates`: `sum` (of an integer expression), `count`, `min`, `max`, `every`, `any`. `evaluate` and `aggregate.apply(total, delta)` throw `unsafe-integer` when a sum or count leaves ±(2^53−1). `foldProperties` describes which aggregates support deltas.
- `metakit/aggregates/sql`: `toSql(aggregate, options)` gives a SQL expression. A sum returns SQL `NULL` if the exact final total is outside the safe integer range. For SQLite, pass `sqliteSum: { maxRows, maxAbsContribution }` with bounds you enforce for each group. Their product must fit a signed 64-bit integer.
- `metakit/machine`: `make`, `Machine`, `MessageOf`, `EmitOf`, `InputOf`. `affordances(machine, state)` sorts its transitions into `available`, `disabled` and `pending` (the guard still needs its input); `dispatch` and `canDispatch(machine, tag, partial)` refuse a tag that names no transition. They live in a module of their own, so a page that only runs transitions carries no partial evaluation. `lift(path, machine)` lifts every transition of a child machine under `path` (which may lead to a nullable or optional field: the transitions are refused while no child is there), and `compose({ state, transitions, children: { Left: lift(left, Counter), Right: lift(right, Counter) } })` makes one machine of them, naming each child transition by its child then its tag (`LeftAdded`; the name `''` keeps the tag). Two transitions that would share a tag do not compile, and `compose` throws. The composed `footprints` are paths from the parent state, so `Graph.analyze` and `foldkit-surface/writes` read them as any machine's.
- `metakit/inspect`: `fieldSpecs`, `toJsonSchema`. A nullable enum lists `null` in its `enum`. A field spec keeps one bound per side, the tightest whichever order the checks were declared, carries `title` and `description` `Option<string>` annotations (whether annotated before or after `Expr.refine`), and says whether the key is `optional`. `toJsonSchema` emits `title` and `description`, gives an array its `items` and a nested struct its `properties`, claims no `type` for a field whose shape it cannot read, and lists only non-optional keys in `required`. A `CalendarDay` travels as an integer, so it carries `x-metakit-domain` and no `format`.
- `metakit/graph`: `analyze`, `pruneStatic`, `queryReadiness`. By default, `queryReadiness` checks that every parameter is bound and the residual lowers to SQL pieces. Pass `prepare` to check your configured SQL or Drizzle renderer. `missing` names unbound parameters and `unsupported` gives a preparation error.
- Declare custom expression operators with `define` from `metakit/operation`. An argument schema can accept several scalar kinds, such as a boolean or an integer. Declare one scalar kind for the result, optionally with null. Its `implement` binds a JavaScript implementation. Use `lowering` from `metakit/operation/sql` for database-specific SQL. Both subpaths are also available under `foldkit-plus/metakit/operation` and `foldkit-plus/metakit/operation/sql`.
- Transition writes take paths from the `state` accessor. Use `Transition.pathsOf(stateSchema, inputSchema, suppliedSchemas)` to get the same accessors outside `Transition.make`. Paths from all three slices work in read expressions.
- `Transition.stepObserved` returns `writes` with the next state and emitted records. A keyed patch names the list, domain key and field. A membership change names the list, and an opaque write names its subtree. No-op writes produce no entries.
- `Machine.intent(machine, tag)` pairs a registered arm's `can(partial)` and `message(input)`. `intent.can` and `Machine.canDispatch` take any supplied values the host already knows. The client message carries the tag and input. The host attaches required supplied values at dispatch.
- `metakit/sql`: `toCheck` (a `CHECK (...)` string that fails where a rule is null), `toWhere` and `toUpdate` (`{ text, params }`), `SqlUnsupportedError`, and `SqlPiece` for the SQL of a foreign operation. `toUpdate`'s `whereId` names a field of the state. `toWhere`'s `table` and `relations` render rows related to a row; a list fold and `arr.append`, `arr.include`, `arr.exclude` are refused by name.
- `metakit/drizzle`: `toCheck`, `toWhere`, `toUpdate`, each over a Drizzle table; the same lowering as `metakit/sql`.
- `metakit/policy`: `make` builds named boolean rules over a row and a principal. `checkConsistent` looks for an unreachable rule and `checkImplication` checks whether one rule implies another.
- `metakit/store`: a store declares `StoreCapabilities` (`{ name, isolation: 'eventual' | 'read-committed' | 'serializable', isolates?: 'transaction' | 'statement', parentRowLock }`); `isolates` is how far the isolation reaches, `'statement'` (one statement or batch, as on D1) when unsaid. A `Requirement` may say where its rule is judged (`judged: 'in-statement' | 'read-first' | 'constraint'`, `'read-first'` when unsaid; `'constraint'`: a constraint the database enforces, such as a foreign key, holds it). `gives(store, capability, judged?)` answers for `'row-atomic'` (any store but an eventual one when judged in the statement that writes or by a constraint; read first, only a serializable store isolating a transaction) and `'parent-serialized'` (by a constraint, any store but an eventual one; otherwise serializable, or read-committed with a parent row lock, and either `isolates: 'transaction'` or the rule judged in the statement that writes). `mount(store, requirements)` throws `StoreRefused`, naming each rule, what it needs, where it is judged and the store; `refused` returns the same list. It imports no expression code.
- `metakit/temporal` (tests and CI): `requirements({ machine, aggregates })` identifies the store capabilities each rule needs. `obligations(machine)` names pairs of transitions with overlapping reads or writes. `discharge(obligation, scenario)` tries each feasible order of the two matched steps before the seeded walk and reports which directions it sampled. `undischarged` keeps a generated pair open until both orders pass and retains failing witnesses. `obligation({ name, shows, over })` declares a custom property. `walk(scenario, { seed, runs })` respects each step's `after`, checks `holds` after each step and reports a failing seed, interleaving and minimal steps.
- `metakit/pairs` (tests and CI): `pairs(machine)` lists each pair of a machine's transitions whose footprints overlap, with `Transition.commutes`' verdict and `why` (for a `True` pair the rule that decided it, such as `an add and an add of "count": …`); `owed(machine)` gives the pairs left undecided as `walk` obligations. `walkPair(machine, ['A', 'B'], { seed, runs })` runs both orders from states and Messages generated from the machine's Schemas and compares the state, the records emitted and which step was refused: `Held`, or `Broken` with the seed that `{ seed, runs: 1 }` replays. `settle(machine, { owner })` declares the pairs in `Temporal.registry` and walks every one: an undecided pair is discharged by a walk that sampled a state, `Held` or `Broken` (a `Broken` one is recorded as "the order matters"); a walk that sampled no state discharges nothing and the pair stays open, and a decided pair is walked too, so a decision that is wrong shows as refuted. `declare` alone leaves the undecided pairs open.
- `Temporal.registry` is the one registry every package adds to (`declare(scope, obligations)`, `record(scope, discharge)`, `decide(scope, pair)`; `makeRegistry()` makes a private one). `registry.report()` lists `open` (each with where it was declared and why it is open), `discharged`, `decided` (with the rule) and `refuted`; its `ok` is false while any is open or refuted. A package adds from a `test/*.obligations.ts` file: the repository's obligations test imports each and fails while one is open, and `npx foldkit-plus laws <file>#report` prints the list.
- `metakit/prove`: `invariant`, `transition`, `policy`, `machine`, `policyConsistent`, `policyAllConsistent`, `policyImplies`. Solver calls use a scoped `Solver` service with a lazy local Z3 default. Set `{ timeoutMs }` to bound solving, or provide a backend with an Effect Layer. Solver proofs name the backend and encoding. A refuted goal carries a counterexample replayed against the Schemas and evaluator. In a machine proof's counterexample report, use `Schema.is` to narrow `before` and `input`. Check the shape of `after` before reading fields because the state schema rejects it.
- `metakit/conformance`: `checkOpSoundness(id)` and `checkAllOps()` hold each primitive operator to one answer from evaluation, partial evaluation and the Tier 3 checker over null, absent keys, NaN, the ends of the safe range and text holding a NUL; `checkProperties(op, properties, { arity, resolve })` and `checkAllProperties()` check declared properties against the evaluator; `checkFoldProperties(fold, properties)` and `checkWriteProperties(way, properties)` (and their `checkAll…`) check the fold and write tables; `checkResidualizeSoundness` does so for an expression over sampled values; `residualSettled(node, env, foreign)` and `residualVerdict(node, env, foreign)` read the value and the verdict off the expression `residualizeNode` leaves, the reference a judge of a partly known environment must answer as; `coreOps` is every operator's descriptor.
- `checkOperation(op, implementations)` in `metakit/conformance` tests a custom operation's claims with boundary cases and seeded inputs from its argument Schemas. Pass a table built with `Operation.implementations`. Idempotence, commutativity and associativity each need a comparison whose two sides return values. An implementation can return `null` as a value. Refusals and automatic propagation of null arguments for a strict operation give no evidence on their own. If `report.failures` says “no sampled equation returned values,” check that the table registers the operation and that its implementation returns values for the declared inputs.
- `metakit/build`: `wrap`, `toNode`, `isExpr`, `call`, `evalNode`, `residualizeNode`, `judgeNode`, `settleNode`, `readsOfNode`, for a language that builds its own constructors on metakit's nodes. `settleNode(node, env, foreign)` gives `Settled.Known({ value })` (null or a `Node.Refusal` among values) or `Settled.Open({ reads, verdict })` where the node rests on what `env` lacks; `judgeNode` is its verdict. Neither builds the expression left over, so a page that judges carries no partial evaluation; `residualizeNode` is for the tools that read that expression.
- `Transition.step(t, state, input, supplied?, options?)` returns `Result<{ state, emitted }, Refused>`; `Transition.run(...)` returns `Result<State, Refused>` (state only); `Transition.stepObserved(...)` adds `writes` (`path` | `membership` | `keyed-field`). `Machine.dispatch(state, { _tag, input, supplied? })` returns `Result<[nextState, emitted], Refused>`, while `Machine.update(state, msg)` returns `[nextState, emitted]` (no-op on refusal). `Machine.attach(machine, prefix, resolvedChild)` merges a resolved `lazyChild` into a new `Machine`.
- `Policy.make({ row, principal, rules: ({ row, principal }) => ({ canEdit: ... }) })` exposes `policy.allow(rule, { row, principal })`, `policy.can(rule, partialEnv)`, and `policy.rules.canEdit` (which passes straight into `Sql.toWhere(policy.rules.canEdit, { dialect: 'postgres', env: { principal } })`).
- Prefer `Operation.define` (`metakit/operation`) + `Language.make` (`metakit/language`) + `lowering`/`lowerings` (`metakit/operation/sql`) for application-defined operations (`Node.foreign` + `metakit/build` `call` is the low-level primitive underneath). Set `claims: { total: true }` on a non-refusing foreign op so `Expr.judge` can short-circuit `false && op(...)`.
- `Money.mul(amount, rate)` infers `rateScale` automatically from a Schema-backed `Decimal` path (pass `{ rateScale }` only for raw literals/unannotated paths). `Arr.sum` returns plain `number`, not a branded `MoneyValue`.
- `metakit/language`: `Language.make(families)` bundles `Operation.define` families with exhaustive `implement`, partial `implementSome`, dialect-checked `sql('sqlite' | 'postgres')`, `describe()` (for server/page comparison and `foldkit-agent/metakit`'s `x-metakit-operations`), and `obligations()`.
- `metakit/store/check` (test-only): `checkStore(declared, adapter)` probes a store adapter against real concurrent races to verify its declared `StoreCapabilities`.
- `Temporal.protocol(names)` in `metakit/temporal`: returns typed `obligation(name, ...)` and `discharge(name, ...)` helpers so misspelled protocol obligation names fail to compile.
